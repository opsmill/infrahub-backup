Backups on Kubernetes no longer send the Neo4j edition query to a CloudNativePG pod. The tool now finds each service's pods by the `infrahub/service` label first, finds Neo4j by the Neo4j Helm chart's pod label, and only uses CloudNativePG pods for the task manager database. Before this, a namespace with a CloudNativePG cluster could make the backup assume Neo4j Community and stop the Infrahub services.
