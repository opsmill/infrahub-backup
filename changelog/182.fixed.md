On Kubernetes, `infrahub-backup create` with Neo4j Community and `infrahub-backup restore` now read the replica count of each workload they scale before they change anything in the deployment, and stop with an error that includes kubectl's message when a count cannot be read. Previously, a workload whose count could not be read was scaled down and came back with 1 replica, with no message at the default log level. A warning that kubectl wrote while it read the count was enough to cause this. `infrahub-collect create --include-backup` runs the same backup and has the same fix. A restore also no longer scales the task manager database (`task-manager-db`) to 1 replica when it restores the task manager data: it keeps the replica count the workload had.
