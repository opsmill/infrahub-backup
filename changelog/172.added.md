Kubernetes deployments whose Neo4j Enterprise or PostgreSQL task-manager database runs outside the cluster can now be backed up and restored with the same `infrahub-backup create` and `restore` commands as any other deployment. Artifacts taken from an external database are byte-compatible with internal ones and restore by the same path, and deployments whose databases are all internal behave exactly as before. When the deployment's own pods take the database username and password from Secret keys, the backup reads the same keys and needs no permissions on secrets. When `infrahub-backup` itself runs as a pod in the Infrahub namespace, it runs the database tools from its own image and creates no Job or Secret, so it needs only the permissions of a backup of internal databases.
